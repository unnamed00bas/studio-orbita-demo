# Фавикон PROMAREN — монограмма PM

Комплект иконок для сайтов и приложений бренда. Архив с этим README и всеми
файлами: `public/brand/PROMAREN-favicon.zip` (на сайте —
`promaren.ru/brand/PROMAREN-favicon.zip`). Пересборка одной командой:
`node scripts/build-favicon.mjs` (с `--site` — установка на promaren.ru).

## Что это

Монограмма PM из букв словесного знака PROMAREN. Буквы построены вектором по
промерам оригинала знака, не набраны шрифтом. У P штамб не доходит до
верхней перекладины — чаша висит отдельно, штамб начинается от её низа. Это
единственная деталь, которую обязательно сохранить: по ней знак узнают
в 16 px. У M средняя вершина усечена и не доходит до базовой линии.

## Файлы

| Файл | Что | Куда |
|---|---|---|
| `pm.svg` | Прозрачная монограмма, медиазапрос внутри файла | `<link rel="icon">` первым в списке: так её понимают Firefox и Safari |
| `pm-light.svg`, `pm-dark.svg` | Те же две версии по отдельности | Фавикон сайта: нужную подставляет скрипт по теме браузера |
| `pm-light.svg`, `pm-light-{16,32,48,120,180,192,512}.png` | Чёрная монограмма без фона | Светлый интерфейс, PNG-фавикон для браузеров без SVG, `mask-icon` для Safari |
| `pm-dark.svg`, `pm-dark-{…}.png` | Белая монограмма без фона | Тёмный интерфейс, графитовые подложки, обложки |
| `pm-on-white.svg`, `pm-on-white-{180,192,512}.png` | Чёрная на белом | Плитки на светлых площадках |
| `pm-on-graphite.svg`, `pm-on-graphite-{180,192,512}.png` | Белая на графите #0C0F13 | apple-touch-icon, Android, PWA-манифест |
| `favicon.ico` | 16, 32, 48 из `pm-light` | `/favicon.ico` в корне сайта |
| `avatar.svg`, `avatar-{512,1024}.png` | Одна буква P графитом #0C0F13 на янтаре #E8A33B, под круглую обрезку | Аватар каналов компании в Telegram и MAX: загружать `avatar-1024.png` |
| `mark-p.svg` | Одна буква P, цвет по теме, без фона | Места уже 120 px, где фон даёт носитель |

## Установка

Обычный HTML:

```html
<link rel="icon" href="/favicon/pm.svg?v=5" type="image/svg+xml">
<link rel="icon" href="/favicon/pm-dark-32.png?v=5" type="image/png" sizes="32x32"
      media="(prefers-color-scheme: dark)">
<link rel="icon" href="/favicon/pm-light-32.png?v=5" type="image/png" sizes="32x32"
      media="(prefers-color-scheme: light)">
<link rel="icon" href="/favicon.ico" sizes="any">
<script>
  // Chrome не понимает ни media у rel="icon", ни prefers-color-scheme
  // внутри SVG-фавикона: нужную версию подставляем сами.
  (function () {
    var m = window.matchMedia && window.matchMedia('(prefers-color-scheme: dark)');
    if (!m) return;
    function set(dark) {
      var href = (dark ? '/favicon/pm-dark.svg' : '/favicon/pm-light.svg') + '?v=5';
      var l = document.querySelector('link[rel~="icon"][type="image/svg+xml"]');
      if (!l) { l = document.createElement('link'); l.rel = 'icon'; l.type = 'image/svg+xml'; }
      l.setAttribute('href', href);
      document.head.appendChild(l);
    }
    set(m.matches);
    m.addEventListener('change', function (e) { set(e.matches); });
  })();
</script>
<link rel="apple-touch-icon" href="/favicon/apple-touch-icon.png?v=3">
<link rel="mask-icon" href="/favicon/safari-pinned-tab.svg?v=3" color="#0C0F13">
```

Фавикон прозрачный: белый в тёмной теме, чёрный в светлой. Одного `media`
для этого мало — его понимают Firefox и Safari, но не Chrome, а медиазапрос
внутри SVG-фавикона Chrome разрешает как светлую тему. Поэтому нужную
версию подставляет скрипт выше; тем же приёмом сделано у GitHub, где в
разметке лежат `favicon.svg` и `favicon-dark.svg`.

Ссылок `rel="icon"` в разметке нет ни одной — иконку целиком ставит скрипт.
Chrome выбирает иконку из того, что нашёл при разборе `<head>`, и дальше её
держит: добавленную скриптом ссылку он не смотрит. Измерено 10.09.2026 по
журналу запросов сервера в тёмной теме — с любой объявленной ссылкой браузер
тянул `favicon.ico` (чёрную), без ссылок вовсе — `pm-dark.svg`.

Запасной путь без скрипта остаётся: `/favicon.ico` браузеры запрашивают из
корня сами. По той же причине в проекте не должно лежать файла, из которого
каркас нарисует ссылку сам, — у Next это `app/icon.svg`.

Скрипт снимает и вешает свою ссылку заново, а не правит ей адрес: Chrome
перечитывает иконку по смене набора ссылок, переписанный `href` пропускает.
Снимать он вправе только свой узел, помеченный атрибутом: снятие чужого
роняет переход по внутренней ссылке целиком.

Next.js (App Router), `metadata.icons`:

```ts
const v = (file: string) => `${file}?v=${ICON_REVISION}`;

icons: {
  icon: [
    { url: v("/favicon/pm.svg"), type: "image/svg+xml" },
    ...[16, 32, 120].flatMap((size) => [
      { url: v(`/favicon/pm-dark-${size}.png`), type: "image/png",
        sizes: `${size}x${size}`, media: "(prefers-color-scheme: dark)" },
      { url: v(`/favicon/pm-light-${size}.png`), type: "image/png",
        sizes: `${size}x${size}`, media: "(prefers-color-scheme: light)" },
    ]),
    { url: "/favicon.ico", sizes: "any" },
  ],
  apple: v("/favicon/apple-touch-icon.png"),
  other: [{ rel: "mask-icon", url: v("/favicon/safari-pinned-tab.svg"), color: "#0C0F13" }],
},
```

Где `apple-touch-icon.png` — это `pm-on-graphite-180.png`, `safari-pinned-tab.svg` —
`pm-light.svg` (маска Safari прозрачная намеренно: цвет ей задаёт атрибут
`color`). В манифесте PWA — `pm-on-graphite-192.png` и
`pm-on-graphite-512.png`, `theme_color` и `background_color` — `#0C0F13`;
адреса внутри манифеста и адрес самого манифеста тоже с `?v=`.

**При каждой замене меняйте адрес, а не имя — всегда, какими бы ни были
заголовки кэша.** Браузер хранит не файл иконки, а нарисованную из него
картинку, в собственной базе иконок, и держит её месяцами независимо от
`Cache-Control`. 08.09.2026 на этом наступили в MarenPay: каталог отдавался
с `max-age=0`, обычный `<img>` с тем же файлом обновился сразу, а во
вкладке висела прежняя чёрная монограмма; тот же файл под адресом с `?v=`
отрисовался белым.

Условие «если долгий кэш», стоявшее здесь раньше, читалось как разрешение
менять содержимое под тем же адресом там, где кэш короткий, — и один проект
так и сделал. Условия у правила нет.

Параметр версии делает адрес новым, а файлы оставляет на месте, и ничто,
что успело запомнить старое имя — кэшированный манифест, чужой агрегатор, —
не упирается в 404. Где есть сервис-воркер, тем же действием поднимите
`CACHE_NAME`: у установленного приложения свой кэш.

Исключение — корневой `/favicon.ico`: браузеры запрашивают его сами, без
ссылки в HTML и без параметров. У тех, чей браузер читает SVG (все
современные), он не используется; у остальных старая иконка доживёт до
конца срока кэша.

## Правила (для брендбука проекта)

1. Знак для иконок и аватаров — монограмма PM (фавикон, иконки приложений)
   или одна буква P (аватары каналов). Ничего другого: ни набранных букв,
   ни знака целиком в квадрате, ни пиктограмм.
2. Два цвета: чёрный на светлом интерфейсе, белый на тёмном. Фон прозрачный.
   Синей, янтарной, серой монограммы нет — цвет в системе за действиями и
   показаниями, знак за именем. Единственная янтарная подложка — аватар
   каналов (правило 3); буква на ней графитовая.
3. На подложке две версии — чёрная на белом и белая на графите
   `#0C0F13`; для iOS, Android и PWA берётся графитовая. Аватар каналов —
   одна буква P графитом `#0C0F13` на янтаре `#E8A33B` (решение владельца
   10.09.2026): аватарку видят в списке чатов на обеих темах сразу, и
   янтарный круг виден на обеих (2,16 : 1 к белому, 7,46 : 1 к тёмному),
   тогда как графитовый на тёмной теме сливается с фоном (1,19 : 1).
   Скруглять углы, добавлять рамку, тень, свечение нельзя: углы скруглит
   система, круг вырежет площадка.
4. Файлы берутся из комплекта, не перерисовываются и не пересобираются в
   редакторах. Изменение пропорций — новая редакция комплекта.
5. Две темы обязательны в каждом размере: чёрные буквы для светлого
   интерфейса, белые для тёмного. Чёрный фавикон в тёмной вкладке не виден,
   и наоборот. Safari SVG-фавикон не читает и возьмёт PNG — там цвет один,
   выберите тот, что чаще у вашей аудитории.
6. Буквы занимают всю ширину поля без фона и 92% на подложке; полей нет:
   их добавит интерфейс, а своё поле только уменьшает буквы. Исключение —
   аватар: площадка режет его кругом, безопасной считается окружность в 80%
   поля, и угол габарита знака должен остаться внутри (половина диагонали
   не больше 0,4 стороны). У одной буквы P это доля высоты до 0,6247,
   в комплекте 0,62; монограмма PM на 92% ширины теряет в круге штамб P и
   ногу M, поэтому в аватары не ставится.
7. Все размеры — вектор со сглаживанием, включая 16 и 32 px; пиксельную
   сетку не делать — в закладках и на плитках она выглядит дешёвой
   картинкой. Штрих иконки 32 при штрихе знака 28, иначе на 48 px
   пропадает просвет в P. Это не повод утолщать знак на других носителях.
